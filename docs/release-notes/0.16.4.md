# Benchy 0.16.4

This release fixes problems that showed up on work machines and on a server managed only from its web page. It goes with engine 0.14.2 and desktop client 0.17.2. Nothing new is added to how tests run.

## A schedule that was missed at the desk can be released

When a Windows machine is set to ask you before each test that needs administrator rights ("At the desk"), and nobody approves a scheduled run, the server holds that schedule on the machine for up to six hours. Until now nothing short of the tray's **Approve scheduled run** ended the hold. Switching the machine to Unattended didn't, and neither did pressing **Run Now**, so the only way out was to copy the schedule.

Now both work. Pressing **Run Now** on the schedule asks the machine again straight away, and a machine switched to Unattended is released as soon as it next checks in, because an unattended agent never asks for approval. If the new run is missed too, the six-hour hold starts again. The text on the schedule page now says so: "Approve it from the tray (Approve scheduled run), press Run Now on the schedule, or it is offered again in about 5 hours."

## An unattended agent that has lost its protection says so

The unattended agent keeps its files in `C:\ProgramData\Benchy\agent-home`, a folder only administrators can change. If someone else gains write access to it (opening the folder in File Explorer and pressing **Continue** is enough), the agent stops running tests that need administrator rights. Before this release nothing told you: the desktop said an administrator had set the computer up, running the setup again quietly reused the same folder, and the agent stayed refused.

The Systems page on the server now shows **Unattended agent refused**, in red, beside such a machine, and hovering over it gives the fix. At the machine, Settings, Server agent explains the problem and has a new **Repair permissions…** button. It asks for administrator approval once (a UAC prompt, or the dialog of a privilege-management tool such as BeyondTrust), builds a fresh protected folder, carries over the pairing and any results not yet uploaded, and leaves the old folder, renamed with `untrusted` in its name, for an administrator to delete. The same repair is available from a terminal as `benchy-engine agent setup-elevated --repair`. Repair needs the 0.14.2 engine; on an older one the page says to update first.

Please don't open `agent-home` in Explorer and press Continue. To see the agent's state, use **Copy details** on the Server agent page.

## Check GitHub gets the engine, components and public catalog too

A server that is managed only from its web page had no way to get the engine, component and public catalog bundles without uploading them by hand. In Server settings, Server updates, **Check GitHub** now fetches those three from the release of the version the server runs, as well as the server update itself. Each line of the result says what it did: imported, already offered, or not on the release. Fetched bundles are checked exactly like uploaded ones. The gaming catalog is never on GitHub, and the result says to upload it on the Test catalog page. To make this dependable, every release from now on attaches all three bundles, server-only releases included. 0.16.3 had no public catalog bundle, so Check GitHub reports it as missing on that release.

## The client notices new updates, and spells "License" the American way

The desktop client now looks for new engine updates each time you reopen Settings, instead of only after a restart. The License field in Build mode and the dialogs that ask you to accept a test's license now use the American spelling. Details are in the client 0.17.2 notes.

## Documentation

There is a new [application test guide](../../documentation/app-test-guide/index.md) for writing a Benchy test for a desktop program on Windows. The user guide now explains that the unattended agent starts when its account logs on, not at boot, so a bench rig needs automatic log-on to run after a restart, and that unattended mode doesn't work where a privilege-management tool such as BeyondTrust hands out administrator rights; use At the desk there.

## Upgrading

On a server installed from the packages, open Server settings, Server updates and press **Check GitHub**, then install 0.16.4. Press **Check GitHub** again afterward to fetch the engine, components and public catalog bundles. Paired machines then offer engine 0.14.2 and client 0.17.2 under Settings, Updates. A machine already set up to run unattended keeps its old engine until you press **Update** in Settings, Server agent (Windows asks once); it needs 0.14.2 before **Repair permissions…** is available.

## Known limits

- Engine and component bundles are compared by sequence number only. After a signing-key change that restarts the numbering, Check GitHub may call a newer bundle "already offered"; upload it by hand.
- Unattended mode still doesn't work on machines where a privilege-management tool gives administrator rights one program at a time. The client now says so; use At the desk there.
- The installer and its files are still unsigned, so Windows shows the publisher as Unknown.
